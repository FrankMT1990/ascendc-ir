# 有效性指标 M0–M9（v2）

**阈值状态声明**：本文所有数值阈值（5%/10%、0.9、0.8、K=5、R=5、效应量 5%）均为**提案值**，在噪声底与试点数据出来之前不视为冻结。在此之前，任何验收结论标注「未达冻结线」。每个阈值冻结时必须写明来源（试点分布、噪声底或外部基准）。

每个指标给两句话：一句大白话（它回答什么），一句精确定义（怎么算）。

## 计时口径与测量清单

性能一律使用 CANNBench kernel-only 口径。每次测量前冻结**测量清单**（manifest），缺一项不得开跑：

- 设备序列号、CANN 版本、锁频命令、清 cache 命令
- warmup 丢弃规则、kernel 名匹配规则（一次 launch 的 `kernel_details.csv` 含多行时按名称+输入 shape 精确过滤，禁止挑较短的行）
- 每候选重复次数、统计量（中位，不是最小值）
- 基线：同一设备、同一 CANN、同一升频流程用同一脚本重测；不重测则基线退出 plateau 的 1.0 阈值与 C4 的绝对判定，只做臂间相对比较
- M0 的测量设备钉死为 C1 同一台 950；2201 只做可移植检查

**离线闭环防污染**：每次离线往返带源码哈希、包哈希与原始 csv 归档；判分脚本只读 csv，不接受手抄时延；上板执行人不得修改源码与包（修改即该候选作废）。

HAP 公式（cann-bench 主指标，C4 用）：

```text
HAP_i = (T_baseline,i − T_HW,i) / ((T_cand,i − T_HW,i) + (T_baseline,i − T_HW,i))
```

`T_HW` 为硬件理论上界，`T_baseline` 为 CANN 基线，均取自 tasks metadata；候选快于基线时 HAP > 0.5。

## 上板前的门（不需要 agent）

| 指标 | 大白话 | 定义 | 通过线（提案） |
|---|---|---|---|
| M0 抽象税 | 生成的代码本身慢不慢 | `tax = T_generated / T_handwritten − 1`，**正值表示生成更慢**。中位 = 各配对税的中位；配对集与重复次数见下 | 中位 ≤ 5%，单对 ≤ 10% |
| M0b 数值一致性 | 生成的代码对不对 | 配对内核在相同输入上逐位一致或与 C1 同一容差 | 必须一致；另报逐位一致率 |
| M4 误拒 / 召回 / 干净 | 好人放行、坏人拦截、不误伤旁枝 | 合法金样本接受率；注入样本期望 ID 集合被触发的比例；实际 ID 集合 == 期望集合的比例 | 误拒 = 0；召回 ≥ 0.9；干净率 = 100% |
| M5 定位命中 | 报错指对地方了吗 | 诊断主调用点与人工金标（file + 源码行片段）一致的比例 | ≥ 0.8（全部规则类，不单列） |

**M0 配对集**（随词汇版本扩展；评审 2026-09-26 第 11 条）：

1. 孪生对照：与生成结构相同的手写（只回答「降级是否多写了指令」）。
2. 去守卫对照：软件流水（剥 prologue/epilogue）的手写——测守卫分支开销，短 tile/短 repeat 形态必测。
3. 官方样例调度对照：官方多核单缓冲写法；IR 表达不了就标为缺口并记录，不计入通过线。
4. 每个已声明可代码生成的 op 至少一对。

每对：固定 shape/dtype，同一 manifest，重复测量次数冻结进清单。孪生对照不单独作为「无抽象税」的证据。

**M4/M5 注入集纪律**（评审第 7 条）：

- 通过线只有一条，由 `evals/m4_m5/run_injection.py` 按它退出非零。
- 分母预注册：每条规则至少 N 个注入（当前 N=1）；V008 在 2201 设备表落地前标「未测」，不计通过。
- 金标在修改检查器之前双人冻结；标注不一致的样本**不得**事后移出分母，单独报告。
- 另设一份不从当前规则反写的故障集（历史编译错误 / agent 试点日志）。
- 合法样本覆盖语料里的原调度，包含刚好卡在 UB、对齐和 event 上限的边界例。

## Agent 对照实验（C1 用）

| 指标 | 大白话 | 定义 | 通过线（提案） |
|---|---|---|---|
| M2 成功率 | 5 次里几次能出活 | 预算与上板上限内，至少产出一个通过数值门且未逃逸内核的 run 比例 | 与对照之差 ≥ −1 次；差 −2 次即任务级不成立 |
| M1 匹配 attainment | 预算花完时最好的内核多快 | 预算 B 处最佳正确（未逃逸）内核时延除进冻结基线时延；报中位与 [min, max] | 中位相对差 ≥ +5% 才算「更高」；< 5% 落入不确定 |
| M3 首次正确 token | 第一个正确内核多早出现 | 到首个通过数值门且未逃逸的候选为止的 token（口径见 claims.md）；未达到记 > B | 两臂成功数均 ≥ 3 才比较中位；否则不确定 |
| M7 逃逸率 | 有没有绕过 IR 直接写 C | IR 臂提交源码中命中逃逸模式的比例（检测脚本随协议冻结） | 逃逸候选作废且不计入 M1/M2/M3 |

## 随 C1 采集的旁路指标

- **无效候选占比**（ADR 0005 的推翻条件）：数值正确但慢于本臂当前最佳 2 倍、或慢于基线 4 倍的上板候选占比。与每 run 上板次数一起报。超过冻结阈值即触发代价模型回摆。
- **检索日志**：两臂对 asc-devkit 示例与本仓 examples/ 的不可见性的执行证据。

## 防误读

- **M1 必须配 M2 看**：M1 只在成功 run 上取中位。5 次只成功 1 次但那次很快，单看 M1 会显得 IR 很好——幸存者偏差。
- **Plateau**：定义与限制见 claims.md（100% 检查点不能单独构成 plateau；plateau 不是 C1 的替代赢面）。
- **M1 基线**：cann-bench tasks metadata 的 BuiltIn `baseline_perf_us`，须同设备同流程重测（见测量清单）。
- **M4/M5 注入错误**：由合法样本只改一处调用点得到。金标双人冻结，不从诊断文案反推。
- **配对（M0）**：手写 C API 与 IR 生成内核的拷贝、计算、同步边一致，只允许 event 分配在等价类内不同。

## 测量顺序

1. 冻结主设备、容差、测量清单、任务 ID 清单、表达力清单、逃逸检测脚本、W1 用例与基线版本。
2. 建仓第一批只实现能测 M0、M4、M5 的词汇；三个门过了再接 agent。
3. 试点 run 定 B 与上板上限，冻结后跑 C1 与 M9。
4. C5 的 Gspan 等单 shape 种子存在之后再定义 shape 集。
