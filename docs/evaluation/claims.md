# 有效性主张 C1–C5（v2.1）

AscendC-IR 是否成立，按五条分开的主张判定。任何单一数字都不构成「IR 有效」的结论；C4、C5 不否决 IR。

一句话版本：**同一个 agent，一半次数用 AscendC-IR 工具链、一半直接写 C API，在表达力对齐的任务集上，哪边产出的内核又快又稳。**

版本历史：v1 初稿；v2 对照 2026-09-26 对抗性评审 16 条重写；v2.1 对照同日复审 12 条修订（判词表唯一化、plateau 移出判赢、对照臂面扫描、B/上板冻结规则）；v2.2 对照第三轮 10 条修订（C1 判词按序表、M2 先于样本数检查、rel 干净比较条件、attainment 公式写死、M9 成功定义、无效候选分母）。三轮评审的逐条处置见 `docs/design/review-response-acceptance-2026-09-26.md`。
## 实验设计

- 两臂：**IR 工具链臂**（写嵌入式 IR，经检查器 + 代码生成）vs **对照臂**（直接写 `.asc` C API）。
- **表达力对齐**：开跑前冻结三张清单——任务 ID 清单、两臂都允许的指令/切分面清单、代码生成支持集清单。任务清单 = 冻结支持集 ∩ cann-bench level1 的**全部**，禁止再删任务；空集记「未测」。**允许面 ⊆ 该版本代码生成会发出的指令集合**；多核切分与 Cube 接口在词汇落地前无条件作废，不因出现在允许面而放行。支持集之外的任务不计入 C1。
- 另设可选的**无限制 C API 臂**（允许全量 C API），单独报告，不回写对齐臂的判决。
- 相同：模型、脚手架、任务书、数值门、shape、设备、CANN 版本、token 预算、每 run 上板次数上限。
- 每臂 R = 5 次独立运行；报告中位与 [min, max]，不做显著性检验。
- 实现不可见：agent 能看算子定义与 oracle，不能看专家内核源码；脚手架不得读取 asc-devkit 示例；**本仓 `examples/` 与参考 `.asc` 对两臂都不可见**，并记录检索日志。
- 数值门：开跑前按 dtype 冻结相对/绝对容差；输入至少包含均匀分布与算子定义允许的边界值。错误内核没有 speedup。M0b 与 C1 共用同一 golden 与同一容差，另报逐位一致率（逐位一致率只报告，不与容差用「或」连成同一个「一致」）。

## token、预算与上板的操作定义

- **token 计量**：B 内计入生成内容与工具回传（含检查器诊断）；以模型 provider 返回的 usage 为准；两臂同一模型同一计法。任务书的固定前置部分两臂等额对齐，不占 B。
- **预算 B**：B = 按提交时间的**前两次成功**试点的首次正确 token 的最大值的 3 倍。试点不足两次成功则追加，追加封顶 4 次并全部归档，不得挑选；仍不足两次则 B 未定、C1 不开跑。试点期间不得改任务书、脚手架与扫描脚本。试点不计入 R=5。
- **上板次数**：每 run 上限 20 次，固定值，不随试点改写；超过即终止该 run。
- **删失**：M3 未达到记 `> B`。

## 逃逸与越面检测

- **IR 臂（M7）**：扫描提交的**源码**（`.py` 及其写出的所有文件），不是生成结果。检测脚本覆盖：字面 `asc_*`、拼接函数名、`exec`/`eval`、另写 `.asc` 再在 IR 里调用、内嵌 C 字符串。
- **对照臂（面扫描，与 M7 同级）**：扫描提交的全部源文件、被包含的头文件与 pack 启动配置；命中对齐清单外的指令、多核切分或 Cube 接口的候选，不进 M1/M2/M3。
- 两臂共用一条作废规则：违规候选不计入 M1/M2/M3；该 run 没有剩余的合规正确内核则记失败。
- 两套扫描脚本与反例样例随协议一起冻结。无限制臂才能计这些候选。

## 判词表（唯一版本，预注册）

**相对差公式**：`rel = median(A_IR) / median(A_control) − 1`，其中 **`A = T_baseline / T_best`**（T_best 为该 run 最佳合规内核的 kernel-only 中位时延，T_baseline 为重测基线时延）。两个文件只写这一行公式；attainment 不得实现成时延或其倒数以外的任何形式。基线未重测时，A 可用同一 metadata 基线做臂间比较，但该基线不得用于 plateau、C4 与无效候选占比。

**前置检查与判词顺序**：先判 M2，再查样本数，最后算 rel/M3。

**任务级判词**（三档，互斥，按序匹配）：

| 判词 | 条件 |
|---|---|
| 不成立 | IR 成功数 ≤ 对照成功数 − 2（不受样本数限制，0/5 对 5/5 落这里）；或两侧成功数相等且 ≥ 3 且 rel ≤ −0.05（同等成功率下的干净性能比较） |
| 不确定 | 任一臂成功数 < 3 或 M1 无法计算；或 rel ≤ −0.05 且 M2 之差为 ±1（条件中位样本不对称，不单独否决） |
| 成立 | 两侧成功数均 ≥ 3，且 M2 之差 ≥ −1 次，且 rel ≥ +0.05，且 M3 中位更低 |

**负载级判词**（无「或」，按序匹配）：

| 判词 | 条件 |
|---|---|
| 未测 | 任务集为空，或全部任务未测 |
| 不成立 | 存在任务不成立 |
| 不确定 | 存在任务不确定或未测 |
| 成立 | 全部任务成立且任务数 ≥ 1 |

**C1 判词**（无「或」，按序匹配）：

| 判词 | 条件 |
|---|---|
| 不成立 | 任一负载不成立 |
| 未测 | W1 未测（无论 W2） |
| 部分成立（W1） | W1 成立且 W2 未测——**只有这一格能叫部分成立** |
| 不确定 | 其余（含 W1 不确定，或 W1 成立而 W2 不确定） |
| 成立 | W1 成立且 W2 成立 |

## 主张表

| 主张 | 判定什么 | 通过线 | 能否否决「IR 成立」 |
|---|---|---|---|
| **C1 工具链** | 整套 IR 工具链（IR + 检查器 + 诊断 + 代码生成）是否优于直接写 `.asc` | 判词表 | 能。这是主主张 |
| **C2 无抽象税** | 同一 schedule 降到 C API 后是否不多付性能 | M0 中位 ≤ 5%、单对 ≤ 10%（分母见 metrics.md），且 M0b 满足与 C1 同一容差 | 能。有税先改代码生成 |
| **C3 检查器拦截** | 非法 schedule 是否在上板前被拒并指向该改的调用点；合法 schedule 是否被放过 | M4 误拒 = 0、召回 ≥ 0.9、干净率 = 100%；M5 定位命中 ≥ 0.8 | 能。误拒不为 0 则不能进 agent 环 |
| **C4 产品性能** | 最好的正确内核相对重测基线有多快 | 报告中位 speedup；HAP 仅作附注（条件见 metrics.md） | 不能 |
| **C5 泛化** | 单 shape 种子收成 dispatcher 后，冻结 shape 集上的几何平均 | 只在 C1 种子存在后计算 | 不能。禁止与 C1 合成一个数 |

主张名从「表示」改为「工具链」：C1 赢了就说明整套环境赢了。要单独主张「表示层」，加一臂「同一 IR、关闭诊断」；该臂不进 C1 判词。

**C3 的升降级**：M9（诊断消融）跑出预注册的最小差值时，C3 升级为「诊断有效」；M9 未跑或未超过差值时，C3 只称「检查器拦截有效」。

## Plateau（独立报告，不参与判词）

- 检查点取预算的 20/40/60/80/100%；某检查点最佳 eligible attainment ≥ 1.0，且之后每个检查点相对它回落 ≤ 3%（相对值，`max(0, a_t − a_later) / a_t`），记为 plateau。
- **100% 检查点没有「之后」，不能单独构成 plateau。**
- `eligible` = 通过数值门且未逃逸、未越面的候选。
- 离线闭环必须在 20/40/60/80% token 处归档**当时**的最佳 eligible 时延；禁止用最终成绩回填中间检查点。
- plateau 是「预算内是否收敛到基线以上」的独立证据；它与 C4 的关系（基线即 C4 分母）必须在报告里写明。

## 边界

- C4 回答「快不快」，不回答「IR 有没有用」；C1 成立而 C4 未超基线，工具链仍然有效。
- C5 的 shape 集（含哈希、日期、托管位置）必须在调 dispatcher 之前提交到仓库；失败 shape 记 0 且使 Gspan 为 0，同时报失败 shape 数。C1 报告模板写明「单 shape，不含泛化」。
- 不计入有效性的数：IR 行数比、编译通过率、单次最好 speedup、把负载或阶段平均成一个分、用 AscendNPU-IR 当对照臂。
- C1 是单次会话对比，不构成学习曲线或长期共同演化的证据；跨 run 迁移另开协议。
- 「合法但很慢」的候选占比随 C1 一起采集（定义与阈值见 metrics.md），超过冻结阈值即触发 ADR 0005 的代价模型回摆。
