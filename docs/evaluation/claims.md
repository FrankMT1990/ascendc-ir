# 有效性主张 C1–C5（v2）

AscendC-IR 是否成立，按五条分开的主张判定。任何单一数字都不构成「IR 有效」的结论；C4、C5 不否决 IR。

一句话版本：**同一个 agent，一半次数用 AscendC-IR 工具链、一半直接写 C API，在表达力对齐的任务集上，哪边产出的内核又快又稳。**

v2 相对 v1 的变化：对照 2026-09-26 对抗性评审（16 条）重写——两臂表达力对齐、任务集与判词预注册、token/预算/逃逸操作定义、测量清单、阈值状态标注。评审结论与逐条处置见 `docs/design/review-findings-2026-09-26.md` 与本文脚注。

## 实验设计

- 两臂：**IR 工具链臂**（写嵌入式 IR，经检查器 + 代码生成）vs **对照臂**（直接写 `.asc` C API）。
- **表达力对齐**：开跑前冻结三张清单——任务 ID 清单、两臂都允许的指令/切分面清单、代码生成支持集清单。支持集之外的任务不计入 C1。多核切分与 Cube 未进词汇前，对应任务的结论只能是「未测」，不得写成主主张被否决。
- 另设可选的**无限制 C API 臂**（允许全量 C API），单独报告，不与表达力对齐臂混判。
- 相同：模型、脚手架、任务书、数值门、shape、设备、CANN 版本、token 预算、每 run 上板次数上限。
- 每臂 R = 5 次独立运行；报告中位与 [min, max]，不做显著性检验。
- 实现不可见：agent 能看算子定义与 oracle，不能看专家内核源码；脚手架不得读取 asc-devkit 示例；**本仓 `examples/` 与参考 `.asc` 对两臂都不可见**，并记录检索日志。
- 数值门：开跑前按 dtype 冻结相对/绝对容差；输入至少包含均匀分布与算子定义允许的边界值。错误内核没有 speedup。M0b 与 C1 共用同一 golden 与同一容差，另报逐位一致率。

## token、预算与上板的操作定义

- **token**：计入全部——提示词、工具回传（含检查器诊断）、生成内容；以模型 provider 返回的 usage 为准；两臂同一模型同一计法。
- **预算 B**：对照臂 2 次试点 run 的「首次正确 token」的 3 倍，冻结进协议；试点不计入 R=5。
- **上板次数**：每 run 上限 20 次，冻结进协议；超过即终止该 run。
- **删失**：M3 未达到记 `> B`；两臂可观测成功数都 ≥ 3 时才比较 M3 中位，否则该任务 M3 判「不确定」。

## 逃逸检测（M7）

- 扫描对象：IR 臂提交的**源码**（`.py` 及其写出的所有文件），不是生成结果（生成结果按设计就含 `asc_*`）。
- 检测脚本覆盖：字面 `asc_*`、拼接函数名、`exec`/`eval`、另写 `.asc` 再在 IR 里调用、内嵌 C 字符串。脚本与反例样例随协议冻结。
- 逃逸候选不进 M1/M2/M3；一个 run 的正确内核全部逃逸时，该 run 记失败。

## 任务集与判词（预注册）

- 任务集：W1 = cann-bench level1 中表达力对齐的向量算子（任务 ID 清单开跑前冻结进 `evals/c1/`）；W2 = level3 Matmul，**Cube 词汇落地前标记「未测」**。
- **任务级判词**（互斥，每种输入只有一格）：
  - **成立**：M2 与对照之差 ≥ −1 次成功，且 M1 中位相对差 ≥ +5%（最小效应量，提案值，待噪声底实测后冻结），且 M3 满足（中位更低或 plateau 更多）。
  - **不成立**：M2 比对照少 ≥ 2 次成功，或 M1 中位相对差 ≤ −5%。
  - **不确定**：其余一切情况，包括任一臂可观测成功数 < 3、区间重叠且点差 < 效应量、M3 因删失不可比。
- **负载级判词**：W1 成立 = 全部任务成立；全部不成立 = 不成立；其余 = 部分成立或不确定（按任务级判词分布写明）。
- **C1 成立** = W1 成立 且 W2 成立（W2「未测」时 C1 记「部分成立（W1）」）。
- 点中位比较必须达到预注册的最小效应量，否则落入「不确定」，不得由实验者事后选择口径。

## 主张表

| 主张 | 判定什么 | 通过线 | 能否否决「IR 成立」 |
|---|---|---|---|
| **C1 工具链** | 整套 IR 工具链（IR + 检查器 + 诊断 + 代码生成）是否优于直接写 `.asc` | 任务级判词表；W1、W2 分开判 | 能。这是主主张 |
| **C2 无抽象税** | 同一 schedule 降到 C API 后是否不多付性能 | M0 中位 ≤ 5%、单对 ≤ 10%，且 M0b 数值一致 | 能。有税先改代码生成 |
| **C3 诊断** | 非法 schedule 是否在上板前被拒并指向该改的调用点；合法 schedule 是否被放过 | M4 误拒 = 0、召回 ≥ 0.9、干净率 = 100%；M5 定位命中 ≥ 0.8 | 能。误拒不为 0 则不能进 agent 环 |
| **C4 产品性能** | 最好的正确内核相对冻结专家/厂商黑盒有多快 | 报告中位 speedup 与 HAP（公式见 metrics.md），不设 IR 成立门槛 | 不能 |
| **C5 泛化** | 单 shape 种子收成 dispatcher 后，冻结 shape 集上的几何平均 | 只在 C1 种子存在后计算 | 不能。禁止与 C1 合成一个数 |

主张名从「表示」改为「工具链」：C1 赢了就说明整套环境赢了。要单独主张「表示层」，加一臂「同一 IR、关闭诊断」；该臂不进 C1 判词。

## Plateau（从判赢条款中独立）

- 检查点取预算的 20/40/60/80/100%；某检查点最佳 eligible attainment ≥ 1.0，且之后每个检查点相对它回落 ≤ 3%（相对值，`max(0, a_t − a_later) / a_t`），记为 plateau。
- **100% 检查点没有「之后」，不能单独构成 plateau。**
- `eligible` = 通过数值门且未逃逸的候选。
- plateau 是「预算内是否收敛到基线以上」的独立证据，不是 C1 的替代赢面；它与 C4 的关系（基线即 C4 分母）必须在报告里写明。

## 边界

- C4 回答「快不快」，不回答「IR 有没有用」；C1 成立而 C4 未超基线，工具链仍然有效。
- C5 的 shape 集（含哈希、日期、托管位置）必须在调 dispatcher 之前提交到仓库；失败 shape 记 0 且使 Gspan 为 0，同时报失败 shape 数。C1 报告模板写明「单 shape，不含泛化」。
- 不计入有效性的数：IR 行数比、编译通过率、单次最好 speedup、把负载或阶段平均成一个分、用 AscendNPU-IR 当对照臂。
- C1 是单次会话对比，不构成学习曲线或长期共同演化的证据；跨 run 迁移另开协议。
- 「合法但很慢」的候选占比随 C1 一起采集（定义与阈值见 metrics.md），超过冻结阈值即触发 ADR 0005 的代价模型回摆。
