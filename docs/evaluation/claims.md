# 有效性主张 C1–C5（冻结版）

AscendC-IR 是否成立，按五条分开的主张判定。任何单一数字都不构成「IR 有效」的结论；C4、C5 不否决 IR。

| 主张 | 判定什么 | 通过线 | 能否否决「IR 成立」 |
|---|---|---|---|
| **C1 表示** | 同一模型、脚手架、任务书、数值门、shape、设备、CANN、token 预算下，AscendC-IR 环境是否优于直接写 `.asc` | 按负载分开判：M2 不低于对照，M1 中位更高，且 M3 更低或 plateau 更多；W1 与 W2 都要过 | 能。这是主主张 |
| **C2 无抽象税** | 同一 schedule 降到 C API 后，kernel-only 时延与手写同结构内核是否一致 | M0 中位 ≤ 5%，单对 ≤ 10%，且 M0b 数值一致 | 能。有税先改代码生成 |
| **C3 诊断** | 非法 schedule 是否在上板前被拒并指向该改的声明；合法 schedule 是否被放过 | M4 误拒 = 0、召回 ≥ 0.9；M5 定位命中 ≥ 0.8 | 能。误拒不为 0 则不能进 agent 环 |
| **C4 产品性能** | 最好的正确内核相对冻结专家/厂商黑盒有多快 | 报告中位 speedup，不设 IR 成立门槛 | 不能 |
| **C5 泛化** | 单 shape 种子收成 dispatcher 后，冻结 shape 集上的几何平均 | 只在 C1 种子存在后计算 | 不能。禁止与 C1 合成一个数 |

## C1 判赢规则

- 处理是**整套环境**：IR + 检查器 + 诊断 + 生成 C API；对照臂是同一 agent 直接写 `.asc`。
- 负载：W1（cann-bench level1 向量算子）与 W2（cann-bench level3 Matmul），分开判定；只过一个记为**部分成立**。
- 每臂 R = 5 次独立 run；报告中位与 [min, max]，不做显著性检验。
- 判赢：M2 不低于对照臂，M1 中位更高，且 M3 中位更低或 plateau 次数更多。中位交叉记为**不确定**。
- 实现不可见：agent 能看算子定义与 oracle，不能看专家内核源码；脚手架不得读取 asc-devkit 示例。
- 逃逸：C1 中嵌入原始 `asc_*` 或 C 片段的候选作废（M7），不进入 M1。

## 边界

- C4 回答「快不快」，不回答「IR 有没有用」；C1 成立而 C4 未超基线，表示仍然有效。
- C5 的 shape 集必须在调 dispatcher 之前冻结。
- 不计入有效性的数：IR 行数比、编译通过率、单次最好 speedup、把负载或阶段平均成一个分、用 AscendNPU-IR 当对照臂。
