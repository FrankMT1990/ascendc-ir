## 3. 开跑前写死的数值规则原文和哈希

**容差与比较式**（manifest v1.2「M0b 数值容差」节，原文见上）：逐元素 `abs(a − b) ≤ atol + rtol × abs(b)`，a=内核输出、b=golden，**atol=rtol=1e-6**，比较在 float32 上进行；任一元素不满足、NaN、dtype 或元素个数不一致即失败。**golden = `torch.add(x, y)`（CPU，float32）**。

**实现脚本** `pack/vector_add_m0/m0b_check.py`（本地归档，sha256 `30967709051128afb0b92f005d24266a86ff6cad35023299f162a1846b56f9f8`），判定核心原文：

```python
ATOL = 1e-6
RTOL = 1e-6
N = 16384
F32 = torch.int32  # 用于逐位比较的视图类型

golden = torch.add(x_cpu, y_cpu)
z = cann_bench.add(x.npu(), y.npu()); torch.npu.synchronize(); a = z.cpu()
if a.dtype != golden.dtype or a.numel() != golden.numel(): FAIL
if bool(torch.isnan(a).any()): FAIL
diff = (a - golden).abs()
tol = ATOL + RTOL * golden.abs()
ok = bool((diff <= tol).all())
bit = int((a.view(F32) == golden.view(F32)).sum().item())
```

**逐位一致率算法**：`a.view(torch.int32) == golden.view(torch.int32)` 逐元素比较原始位模式，**比较前没有任何舍入**（容差判定与逐位判定都在原始 f32 结果上独立进行，逐位不构成容差的「或」分支）。

**计时用的是哪一组输入**：计时 run 的输入由 cann-bench harness 按任务定义生成——`task/level1/add_m0/cases.yaml`（本地归档）冻结 case 1：`input_shape [[16384],[16384]]`、dtype float32、**value_range [-2, 2]（两输入同）**，note：「M0-frozen: TILE=2048f32 x TILES=8, single-core, add_vf data_len=2048 (VF repeat_time=32)」。harness 随机种子由 `--eval-seed` 控制，**该 seed 与完整 CLI 未留档（如实披露）**；冻结的是 shape/dtype/value_range。M0b 用的是与计时无关的冻结输入组 G1/G2（构造规则原文见第 2 项清单）。
