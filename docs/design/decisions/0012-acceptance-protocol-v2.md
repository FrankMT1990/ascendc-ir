# 0012 验收协议 v2：预注册、表达力对齐、测量清单

状态：已确认（2026-09-26，对抗性评审 16 条之后）。修订 ADR 0005 的推翻条件采集方式。

## 背景

grok-4.7-xhigh 评审（16 条全部属实，逐条处置见 `docs/design/review-response-acceptance-2026-09-26.md`）暴露 v1 验收方案的结构性漏洞：两臂表达力不对等、M0 比值方向可被误读、plateau 把基线性能偷渡进 C1、token/预算/逃逸无操作定义、注入集撑不起门禁地位、阈值无依据却写「冻结」。

## 决定

1. **表达力对齐**：开跑前冻结任务 ID 清单、两臂允许的指令/切分面清单、代码生成支持集清单；支持集外的任务不计入 C1。另设可选的无限制 C API 臂单独报告。
2. **判词预注册**：任务级判词四档互斥（未测/不成立/成立/不确定，兜底行永远最后），含最小效应量与删失规则；负载级与 C1 判词无「或」按序匹配（未测在不成立之前）；规则写死。
3. **操作定义**：token 计全部（含工具回传；任务书固定前置两臂等额不占 B）；B = 按提交时间的前两次成功试点的首次正确 token 最大值 × 3，试点不足两次成功则追加（封顶 4 次、全部归档、不得挑选），仍不足则 B 未定、C1 不开跑；每 run 上板 ≤ 20 次（固定，不随试点改写）；逃逸只扫 IR 臂源码，对照臂面扫描同等级（全部源文件 + 头文件 + pack 配置），违规候选不计入任何指标。
4. **测量清单**：设备、CANN、锁频、清 cache、kernel 行过滤、重复次数、中位统计量逐项冻结；基线须同设备同流程重测，否则退出绝对阈值；离线往返带源码/包/csv 哈希，判分只读 csv。
5. **阈值状态**：全部数值阈值标注「提案值」，附来源或待测项；噪声底实测前验收结论标注「未达冻结线」。
6. **M9 改三档**（完整诊断 / 仅 message / 仅规则 ID，全不上板），成功 = 5 轮内同时满足：trace 完成、block 诊断为空、被注入的调用仍在 trace 结果里（操作数与注入点相同；注释和未执行分支不算）；M9 失败则 C3 降级为「检查器拦截有效」。
7. **M0 配对集**扩为四类：孪生、去守卫软件流水、官方样例调度（表达不了记缺口）、每个可生成 op 至少一对。
8. **无效候选占比**随 C1 采集（分母 = 全部上板次数；分子 = 数值错误或正确但慢于重测基线 4 倍），超冻结阈值（0.5，提案）触发 ADR 0005 回摆。
9. **表达力回测**分母改为完整种子清单（gap 留在分母），回测只用未看过的内核；准入门槛 k=2。

## 后果

- claims.md / metrics.md 重写为 v2；run_injection.py 通过线唯一化（误拒=0、召回≥0.9、定位≥0.8、干净率=100%）。
- C1 主张名从「表示」改为「工具链」；表示层的独立主张需要「同一 IR 关诊断」臂。
- C1 报告模板必须写明「单 shape，不含泛化」；不构成学习曲线证据。

## 推翻条件

- 噪声底实测显示 5% 效应量不可分辨 → 效应量与 R 重议。
- 离线闭环往返成本使 R=5 × 任务数不可行 → 任务集收缩规则预注册，不事后挑选。
