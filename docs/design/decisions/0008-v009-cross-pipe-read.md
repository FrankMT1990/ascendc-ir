# 0008 新增 V009：跨 PIPE 读取必须先经 sync

状态：已确认（2026-09-25）

## 背景

PR3 实现 V003 时发现规则集有洞：V003 只检查**已声明**的 sync 的配对，「生产 PIPE 写了 buffer、消费 PIPE 没经 sync 直接读」没有规则抓。这是知识仓 runbook「共享 UB 跨流水线复用须按方向显式同步」的核心场景，也是 C API 编程最常见的错值/hang 来源。

## 决定

新增 V009：每次读取 buffer 槽位时，若最近一次写入在另一条 PIPE，则写入之后、本次读取之前必须存在覆盖该槽位的 sync。诊断指向读取调用点。spec、实现、注入样本、单测同步落地。

## 后果

- 规则集从 8 条变 9 条；M4/M5 注入集含 V009 样本（删除 sync 行）。
- 教训固化：规则集评审时多问一句「这个错误类的**缺失形态**有没有规则抓」。

## 推翻条件

- 不适用；这是安全性规则的补漏。若 V009 与 V003/V004 出现重复诊断，可在实现层去重，但规则语义保留。
